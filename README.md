# NetAI Monitor

Десктоп-приложение для интеллектуального анализа сетевых инцидентов (Zabbix)
и конфигураций сетевого оборудования (Oxidized) на локальной LLM (Ollama),
с RAG-обогащением контекста из истории предприятия и обратной связью
инженера («обучение на ошибках» через приоритетный RAG-контекст, а не
дообучение весов модели).

Полная пошаговая инструкция по развёртыванию на предприятии — [DEPLOYMENT.md](DEPLOYMENT.md).

## Возможности

- **Дашборд** — сводные метрики, конвейер анализа, график инцидентов.
- **Алерты** — история инцидентов из общей БД, поиск/фильтры, вкладка
  «Закрытые» (с отметкой пропущенных), детектор дублей. Сам опрос Zabbix и
  анализ через Ollama выполняет фоновый сервис (см. «Сервис реального
  времени» ниже) — работает независимо от того, открыт ли десктоп-клиент.
- **Конфигурации** — diff-ревью и полный аудит конфигурации на best practice.
- **Обратная связь инженера** — правка вывода ИИ и фактического решения,
  которое приоритетно используется RAG для похожих будущих случаев.
- **Генератор** — конструктор синтетических алертов/конфигураций с доставкой
  в реальном времени, без похода в боевой Zabbix/Oxidized.
- **Аналитика** — метрики эффективности (аналог MTTR, покрытие проверки,
  повторяемость инцидентов) и экспорт истории в PDF/Excel.
- **Настройки** — проверка подключений к Zabbix/Oxidized/Ollama в один клик.

## Требования

- Python 3.11+ (для запуска из исходников)
- PostgreSQL 14+ с расширением [pgvector](https://github.com/pgvector/pgvector) —
  опционально: если недоступен, приложение автоматически переключается на
  локальный SQLite-файл (демо-режим без RAG, см. `backend.py`).
- [Ollama](https://ollama.com) с моделью анализа (`gemma3:4b`, `qwen2.5:3b` и т.п.)
  и моделью эмбеддингов `nomic-embed-text` — опционально, без неё работает
  офлайн-анализ по правилам (`RuleBasedAnalyzer`).

## Запуск из исходников

```bash
pip install -r requirements.txt
python main.py
```

Параметры подключения к PostgreSQL задаются либо на вкладке **Настройки →
PostgreSQL** в самом приложении (сохраняются в `%APPDATA%\NetAI Monitor\
postgres_connection.json`), либо переменной окружения `NETAI_DB_DSN` (имеет
приоритет, удобно для CI/скриптов):

```bash
setx NETAI_DB_DSN "dbname=netai_monitor user=postgres password=... host=localhost"
```

Если PostgreSQL на Windows с русской локалью — проверьте, что `lc_messages`
в `postgresql.conf` не `Russian_Russia.1251` (иначе psycopg2 иногда падает
с `UnicodeDecodeError` вместо реальной причины отказа подключения);
поставьте `lc_messages = 'C'` и перезапустите службу PostgreSQL.

Окно запускается развёрнутым на весь экран.

## Сервис реального времени

Опрос Zabbix и анализ через LLM выполняет **отдельный процесс**
(`realtime_service.py`), а не сам десктоп-клиент — это специально: если бы
опрос жил внутри GUI, анализ останавливался бы вместе с закрытием окна.
Сервис читает и пишет ту же БД (PostgreSQL или, в офлайн-режиме, локальный
SQLite), что и десктоп-приложение, поэтому предполагается, что он работает
постоянно на том же сервере, где развёрнуты PostgreSQL и Ollama — тогда
десктоп-клиенты у всех инженеров в сети сразу видят актуальную картину,
просто читая общую историю, независимо от того, запущены ли они сами.

```bash
python realtime_service.py
```

Опрашивает Zabbix раз в минуту, анализирует новые (и ранее не
распарсившиеся) проблемы, определяет закрытие (пропали из активных —
`resolved_at` в БД) — та же логика, что раньше была в `AlertsTab`, вынесена
в `realtime_engine.py` без зависимости от Qt.

Особенности, рассчитанные на постоянную работу службой:

- **Свои настройки на сервере** — `%PROGRAMDATA%\NetAI Monitor\service_config.json`
  (см. `service_config.py`): параметры Zabbix, DSN к PostgreSQL, интервал
  опроса, `ollama_host`. Именно там, а не в общей БД, потому что доступ к
  Zabbix есть только у серверной машины, `ollama_host` у сервера и у
  клиентов разный, а служба Windows не видит `%APPDATA%` пользователя.
- **Логи в файл с ротацией** — `%PROGRAMDATA%\NetAI Monitor\logs\realtime.log`
  (5 × 5 МБ): у службы нет консоли, и весь `stdout` иначе пропал бы.
- **Ожидание PostgreSQL** — при недоступной БД служба не падает и не
  подменяет её локальным SQLite (иначе анализ уходил бы в файл, которого
  никто не видит), а ждёт и повторяет попытку.
- **Защита от двух копий** — файловая блокировка: служба и случайно
  запущенный вручную скрипт не будут дублировать опрос и вызовы LLM.
- **Heartbeat в БД** — таблица `service_heartbeat`: состояние, время
  последнего опроса, доступность Zabbix **для сервера**, сводка цикла.
  Десктоп-клиенты показывают это в Настройках (вкладка «Сервис реального
  времени») — им самим Zabbix недоступен, проверить его локально нечем.

Установка службой Windows (нужен [NSSM](https://nssm.cc/download)):

```powershell
.\tools\install_service.ps1            # установить (от администратора)
.\tools\install_service.ps1 -Remove    # удалить
```

Подробно — в [DEPLOYMENT.md](DEPLOYMENT.md), шаг 5.

## Тема оформления

По умолчанию — светлая (спокойная, для целого рабочего дня). Переключение
на тёмную — вкладка **Настройки → Оформление**, применяется после
перезапуска приложения (хранится в `%APPDATA%\NetAI Monitor\ui_theme.json`).

## Логотип / иконка

`assets/icon.ico` — сгенерирован скриптом `tools/generate_icon.py` (нужен
Pillow: `pip install pillow`). Чтобы поменять дизайн — правьте константы
цветов и геометрию узлов в этом скрипте и перезапустите его, затем
пересоберите .exe и установщик.

## Типографика

Интерфейс использует **Inter** (геометричный нейтральный sans) для текста и
**JetBrains Mono** для данных/идентификаторов/diff'ов. Оба — вариативные
шрифты (один .ttf-файл покрывает все насыщенности), лежат как файлы в
`assets/fonts/` (SIL Open Font License — см. `OFL-*.txt` там же) и
регистрируются в Qt при старте (`gui.load_bundled_fonts`), поэтому
рендерятся одинаково независимо от того, что установлено на компьютере —
не системный шрифт по умолчанию.

## Сборка в .exe

```bash
pip install pyinstaller
pyinstaller netai_monitor.spec --clean
# результат: dist/NetAI-Monitor/NetAI-Monitor.exe
```

Иконка (`assets/icon.ico`) и метаданные версии файла (`version_info.txt` —
компания, описание, версия — видно во вкладке «Подробнее» в свойствах
exe) встраиваются автоматически через `netai_monitor.spec`.

## Сборка установщика (Windows)

Требуется [Inno Setup](https://jrsoftware.org/isinfo.php). После сборки exe:

```bash
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss
# результат: installer_output/NetAI-Monitor-Setup.exe
```

Установщик работает без прав администратора, ставит приложение в
пользовательский профиль, создаёт ярлыки в меню «Пуск» и (по желанию) на
рабочем столе, регистрируется в «Установка и удаление программ» — со своей
иконкой и корректной информацией об издателе/версии.
