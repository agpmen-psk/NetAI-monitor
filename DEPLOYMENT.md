# Развёртывание NetAI Monitor на предприятии

Пошаговая инструкция по вводу в эксплуатацию с нуля: от чистого сервера до
работающей системы у всех инженеров NOC. Рассчитана на IT-специалиста,
разворачивающего систему, а не на конечного пользователя интерфейса.

## Архитектура

Три уровня, физически разделённых:

| Компонент | Где живёт | Роль |
|---|---|---|
| PostgreSQL + pgvector, Ollama | сервер (локально, порты наружу НЕ открываются) | хранилище и LLM |
| `realtime_service.py`, `job_worker.py`, `api_server.py` | сервер, постоянно (три отдельные службы Windows) | вся серверная логика |
| `NetAI Monitor` (десктоп) | ПК каждого инженера | тонкий клиент — только HTTP до `api_server.py` |

```
Zabbix ──(только с сервера, напр. через L2TP-туннель)──┐
                                                        ▼
                        realtime_service.py  ──анализ──▶ Ollama (localhost)
                                   │
                                   ▼ пишет инциденты + heartbeat
                             PostgreSQL (localhost, не открыт наружу)
                                   ▲
                                   │ забирает задания из очереди, пишет результат
                             job_worker.py  ──анализ──▶ Ollama (localhost)
                                   ▲
                                   │ читает/пишет, ставит задания в очередь
                             api_server.py (порт 8000)
                                   ▲
                                   │ HTTPS + токен сессии — ЕДИНСТВЕННОЕ, что
                                   │ видят десктоп-клиенты
                        десктоп-клиенты инженеров (LAN, или интернет через туннель)
```

Ключевое следствие: **десктоп-клиенты не обращаются ни к PostgreSQL, ни к
Ollama, ни к Zabbix/Oxidized напрямую.** Всё — через `api_server.py`. Это
даёт: один порт наружу вместо четырёх, авторизацию по логину/паролю вместо
общего пароля от БД на каждом ПК, и возможность в будущем спрятать сервер
за HTTPS/обратным прокси, не трогая клиентов.

Долгие LLM-операции (аудит конфига, сравнение «с RAG / без RAG», приём
данных из Генератора) `api_server.py` сам не выполняет — он бы держал
поток занятым 30–120 секунд и тормозил всех остальных клиентов. Вместо
этого он кладёт задание в таблицу `job_queue`, а обрабатывает его
`job_worker.py` — независимо от опроса Zabbix (`realtime_service.py`), так
что падение одной службы не тянет за собой другую.

Ниже — порядок, в котором это разумно поднимать: сначала инфраструктура на
сервере, потом все три службы, потом клиенты у инженеров.

---

## Шаг 1. PostgreSQL + pgvector на сервере

1. Установите PostgreSQL 14+ (если ещё не установлен).
2. Установите расширение [pgvector](https://github.com/pgvector/pgvector) —
   на Windows проще всего взять готовую сборку под вашу версию PostgreSQL,
   на Linux — собрать из исходников (`make && make install`) или поставить
   пакет `postgresql-*-pgvector`, если он есть в вашем дистрибутиве.
3. Создайте базу данных:
   ```sql
   CREATE DATABASE netai_monitor;
   ```
   Таблицы, индексы и само расширение `vector` в этой базе приложение
   создаст автоматически при первом подключении (см. `db.py: SCHEMA`) —
   вручную создавать их не нужно, только саму базу.

**PostgreSQL наружу (даже в локальную сеть) открывать НЕ нужно** — его
видят только три серверных процесса, все на одной машине, через
`localhost`. Порт 5432 должен слушать только `localhost` (по умолчанию так
и есть — ничего дополнительно настраивать не требуется).

### Локаль на Windows (важно)

Если PostgreSQL установлен с русской локалью, по умолчанию сервер отвечает
системными сообщениями в кодировке Windows-1251 — `psycopg2` пытается
декодировать их как UTF-8 и падает с `UnicodeDecodeError`, маскируя
реальную причину отказа подключения (неверный пароль, порт и т.п.). В
`postgresql.conf`:
```
lc_messages = 'C'
```
и перезапустить службу PostgreSQL.

## Шаг 2. Ollama на сервере

```bash
ollama pull gemma3:4b          # или qwen2.5-coder:7b — модель анализа, любая под ваши мощности
ollama pull nomic-embed-text   # модель эмбеддингов, нужна для RAG
```

К Ollama обращаются только `realtime_service.py` и `job_worker.py` — оба
на той же машине. **Открывать Ollama в сеть не нужно** (в отличие от
прежней архитектуры, где к ней ходили и десктоп-клиенты) — она остаётся на
`localhost:11434`, как по умолчанию.

---

## Шаг 3. Получить приложение на сервере

```bash
git clone https://github.com/agpmen-psk/NetAI-monitor.git
cd NetAI-monitor
pip install -r requirements.txt
```

Python 3.11+ нужен на сервере (для всех трёх служб) и на любой машине,
откуда будете собирать `.exe` для инженеров (см. шаг 6).

## Шаг 4. Настроить `service_config.json`

Один файл на все три серверных процесса — единственный источник истины для
Zabbix/Oxidized/Ollama/PostgreSQL/API на сервере:

```
%PROGRAMDATA%\NetAI Monitor\service_config.json
```

Файл создаётся автоматически при первом запуске любой из служб (или
скриптом установки, шаг 5). Заполните:

```json
{
  "postgres_dsn": "dbname=netai_monitor user=postgres password=... host=localhost port=5432",
  "zabbix_url": "http://10.10.11.25/zabbix",
  "zabbix_user": "Admin",
  "zabbix_password": "...",
  "oxidized_url": "http://10.10.11.30:8888",
  "ollama_host": "http://localhost:11434",
  "ollama_model": "gemma3:4b",
  "embedding_model": "nomic-embed-text",
  "use_synthetic_data": false,
  "poll_interval_seconds": 60,
  "api_host": "0.0.0.0",
  "api_port": 8000
}
```

`api_host: "0.0.0.0"` — API слушает на всех интерфейсах сервера, чтобы
десктоп-клиенты в локальной сети подключались по его IP. Публикация
API-порта наружу в интернет (на время защиты диплома) — отдельный шаг,
которым можно заняться позже, независимо от остального: способ (Cloudflare
Tunnel, port-forward + сертификат и т.п.) не влияет на сам API.

Изменения в этом файле применяются только после перезапуска **всех трёх**
служб.

После первого запуска `api_server.py` можно редактировать этот файл прямо
из приложения: вкладка **Настройки** → «Настройки сервера» (видна только
администратору) — читает и пишет тот же файл через `GET/PUT
/admin/service-config`.

## Шаг 5. Установить и запустить три службы Windows (NSSM)

1. Скачайте [NSSM](https://nssm.cc/download) и положите `nssm.exe` в
   `tools\nssm.exe` (или добавьте в `PATH`).
2. В PowerShell **от администратора**, из корня проекта — установите
   каждую из трёх служб отдельным вызовом:

```powershell
.\tools\install_service.ps1 -Service realtime
.\tools\install_service.ps1 -Service worker
.\tools\install_service.ps1 -Service api
```

| -Service | Имя службы | Что делает |
|---|---|---|
| `realtime` | `NetAIMonitorRealtime` | опрос Zabbix, анализ через LLM |
| `worker` | `NetAIMonitorJobWorker` | очередь LLM-заданий (аудит/diff конфигов, сравнения, Генератор) |
| `api` | `NetAIMonitorApi` | FastAPI/uvicorn — точка входа для десктоп-клиентов |

Все три — с автозапуском при загрузке компьютера и автоперезапуском при
падении процесса. Управление — `services.msc` или
`nssm start/stop/restart <имя службы>`. Удаление —
`.\tools\install_service.ps1 -Service <realtime|worker|api> -Remove`.

Запуск вручную (для проверки/отладки) по-прежнему работает:
```bash
python realtime_service.py
python job_worker.py
python api_server.py
```
Вторая копия `realtime_service.py`/`job_worker.py` не запустится — держат
файловую блокировку, иначе два процесса дублировали бы опрос/анализ.

### Первый администратор

При первом запуске `api_server.py`, если в таблице `users` ещё никого нет,
создаётся пользователь `admin` со случайным паролем — он **один раз**
печатается в лог:
```
%PROGRAMDATA%\NetAI Monitor\logs\api_server.log
```
строка вида `Создана первая учётная запись администратора: логин 'admin',
пароль '...'`. Войдите с ним в десктоп-клиенте и смените пароль (вкладка
Настройки → «Пользователи» → «Сбросить пароль» для самого себя), либо
сразу заведите именных администраторов и отключите общий `admin`.

### Как понять, что службы работают

- **Из интерфейса приложения (с любого ПК)** — вкладка **Настройки**,
  карточка «Серверные службы»: отдельно состояние опроса Zabbix и очереди
  LLM-заданий, когда была последняя отметка, доступен ли Zabbix серверу.
- **Логи** (с ротацией, 5 файлов по 5 МБ каждый):
  ```
  %PROGRAMDATA%\NetAI Monitor\logs\realtime.log
  %PROGRAMDATA%\NetAI Monitor\logs\job_worker.log
  %PROGRAMDATA%\NetAI Monitor\logs\api_server.log
  %PROGRAMDATA%\NetAI Monitor\logs\service-std{out,err}-{realtime,worker,api}.log   — только ранние ошибки запуска
  ```

Если PostgreSQL в момент старта ещё не поднялся (типично при перезагрузке
сервера — службы стартуют в произвольном порядке), ни одна из трёх служб
не падает: пишет в лог «PostgreSQL недоступен… Повтор через 15 сек» и
поднимается сама.

## Шаг 6. Раздать десктоп-клиент инженерам

Десктоп больше не хранит никаких серверных параметров (PostgreSQL/Zabbix/
Ollama) — только адрес API-сервера, который каждый инженер один раз вводит
на экране входа.

Два варианта раздачи:

**А. Установщик (рекомендуется для инженеров без Python)** — собирается
один раз на любой Windows-машине с установленным проектом:
```bash
pip install pyinstaller
pyinstaller netai_monitor.spec --clean
# результат: dist/NetAI-Monitor/NetAI-Monitor.exe

# затем (нужен Inno Setup — https://jrsoftware.org/isinfo.php):
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss
# результат: installer_output/NetAI-Monitor-Setup.exe
```
Раздайте `NetAI-Monitor-Setup.exe` инженерам — ставится без прав
администратора, в пользовательский профиль.

**Б. Из исходников** — на машине с Python:
```bash
git clone https://github.com/agpmen-psk/NetAI-monitor.git
cd NetAI-monitor
pip install -r requirements.txt
python main.py
```

### Первый вход

При первом запуске откроется окно входа с тремя полями:
- **Сервер** — адрес API, например `http://192.168.1.10:8000` (или
  публичный адрес, если API опубликован в интернет — см. шаг 4);
- **Логин / Пароль** — выданные администратором (см. шаг 5);
- **Запомнить меня** — сохраняет токен сессии в Диспетчере учётных данных
  Windows (не в файле на диске), чтобы не вводить пароль при каждом
  запуске; без галочки сессия живёт 12 часов, с галочкой — 30 дней.

Роль (`инженер`/`администратор`) назначается на сервере и видна в
приложении на вкладке Настройки — из клиента сменить свою роль нельзя,
только администратор может выдать роль другому пользователю (вкладка
Настройки → «Пользователи», видна только администратору).

## Шаг 7. Проверка работоспособности

1. Войдите в десктоп-клиент под администратором → вкладка **Настройки**:
   карточка «Серверные службы» должна показывать «состояние: работает» для
   обеих служб; карточка «Настройки сервера» должна успешно загрузиться
   (значит API видит `service_config.json` и саму БД).
2. Дождитесь следующего цикла опроса (интервал — `poll_interval_seconds` в
   `service_config.json`, по умолчанию 60 сек) — новый алерт должен
   появиться во вкладке **Алерты** и всплыть тостом в правом нижнем углу.
3. На вкладке **Конфигурации** нажмите «Проверить diff» на любом
   устройстве — должно появиться задание, обработанное `job_worker.py`, и
   результат появиться в истории (обычно 5–30 секунд, зависит от модели).
4. Вкладка **Чат** — задайте вопрос, должен прийти осмысленный ответ (сам
   запрос к Ollama выполняет `api_server.py` синхронно).
5. Вкладка **Дашборд** должна показывать ненулевые метрики после того, как
   накопится история.

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `UnicodeDecodeError` при подключении к PostgreSQL (в логе службы) | `lc_messages` в русской локали | См. «Локаль на Windows» в шаге 1 |
| Окно входа: «Нет связи с сервером» | Неверный адрес/порт, `api_server.py` не запущен, файрвол блокирует порт 8000 | Проверить `nssm status NetAIMonitorApi`, лог `api_server.log`, файрвол на сервере |
| Окно входа: «Неверный логин или пароль» | Опечатка, либо учётная запись отключена администратором | Проверить у администратора (вкладка Настройки → Пользователи) |
| Инциденты не появляются | `realtime_service.py` не запущена или упала | Настройки → «Серверные службы»; лог `%PROGRAMDATA%\NetAI Monitor\logs\realtime.log` |
| Задания (diff/аудит/сравнение) зависают в статусе «выполняется» надолго | `job_worker.py` не запущена или упала | Настройки → «Серверные службы» (строка «Очередь LLM-заданий»); лог `job_worker.log` |
| `RAG недоступен`/сравнение без контекста | Нет модели `nomic-embed-text` в Ollama на сервере | `ollama pull nomic-embed-text` на сервере, перезапустить `realtime_service.py` и `job_worker.py` |
| Чат работает, но отвечает не на то | Модель анализа (`ollama_model` в `service_config.json`) не скачана или сервер Ollama недоступен | Проверить `ollama list` на сервере, лог `api_server.log` |
| «Служба уже запущена» в логе и служба выходит | Уже работает копия (служба Windows + ручной запуск) | Защита от дублирования анализа — остановите лишнюю копию (`nssm stop <имя>` либо закройте консоль) |
| Нужен второй администратор / отключить учётную запись | — | Вкладка Настройки → «Пользователи» (только для роли admin) |
